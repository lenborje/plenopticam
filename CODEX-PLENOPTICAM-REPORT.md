Primary interpreter: `/opt/homebrew/bin/python3`, **CPython 3.14.7**, macOS 27.0.1, Apple Silicon arm64, Clang 21. Homebrew/system Python was not modified. No second Python version was necessary: the encountered application failures are removed dependency APIs, not a CPython-specific regression.

GUI tests require a graphical macOS session and ran outside the execution sandbox.

## Changes

Packaging:

- Explicit isolated setuptools build backend in `pyproject.toml` (setuptools >=77).
- Read the version with standard-library code instead of importing the application; read README directly instead of using runtime docutils during setup.
- Load py2app only for an explicitly requested `py2app` build; ordinary installation does not bundle an application.
- Explicitly include package configuration and GUI icons in wheels.
- Correct `MANIFEST.in` capitalization and include requirements and the reports. The prior source archive omitted `requirements.txt` and therefore could not rebuild from its own contents.

Dependencies:

- Remove the PyInstaller 5.13.1 runtime requirement; standalone bundling remains separate, untested work.
- Replace `tifffile==2022.4.8` with `tifffile>=2025.6.11`, following Doridian's tested modernization direction.
- Replace `color-matcher==0.4.0` with `color-matcher>=0.6.0`; the application API still works.
- Preserve depth support by using immutable `Doridian/depthy` revision `35a21fb86722bb9de8e40b6b3f61b1b3be365b2f`. It replaces `scipy.misc.face` with `scipy.datasets.face`, replaces `np.float`, and avoids the old setup-time imports. No local monkey patch or runtime shim is used. Original Depthy and these changes are GPL-3.0.
- Other lower bounds remain unless an actual incompatibility required changing them. Resolution selected current maintained arm64 wheels.

Application compatibility:

- Adapt Doridian/plenopticam `f38349f036791a48c24ee78dbd3d5bcca76ff715`: replace removed `interp2d` with regular-grid `RectBivariateSpline`. Preserve x/y conventions with both transposes and explicitly preserve linear/cubic/quintic degrees. In particular, local alignment retains linear interpolation. [SciPy's transition guide](https://docs.scipy.org/doc/scipy/tutorial/interpolate/interp_transition_guide.html) documents this equivalence.
- Adopt Gor G `c4c5a3246584ec8e1a01c61420bbcd2952632123`: distinguish RAW files from C.x bundle suffixes. The bug was reproduced independently with dispatch tests.
- Replace removed Pillow `ImageDraw.textsize` with `textbbox`, retaining centered notification text.
- Pass reshape dimensions positionally instead of NumPy's removed `newshape` keyword in viewer loading.
- Add small offline regressions and a reproducible real-camera integration runner. No calibration or reconstruction algorithm was redesigned.

## Physical-camera calibration

The original `~/Documents/caldata-B5151215780.tar` is 1,766,347,264 bytes. It has **144 members under `unitdata/`**:

- Seven JSON files: `mla_calibration.json`, `unit_info.json`, `bipos.json`, two tracking-measurement files, `bipos_1500mm.json`, and `cal_file_manifest.json`.
- `HOTPIXEL.BIN`.
- 34 sets `MOD_0000` through `MOD_0033`, each with RAW, TXT, GCT and HST files.

`unit_info.json` identifies camera serial **B5151215780**, matching the raw image. `mla_calibration.json` contains per-zoom/focus geometry (pitch, rotation, offsets, exit-pupil distances); the manifest maps each calibration member to a SHA-1 reference. TXT files contain white-image capture metadata and RAW files the sensor calibration exposures.

PlenoptiCam already supports this genuine camera-export format directly. Supply a `.tar` file or a directory containing calibration archives. `CaliFinder` reads the image geometry correction reference, matches the manifest GCT entry, chooses its corresponding RAW/TXT pair, and decodes the white image. For this photograph it selects **MOD_0023.RAW**. No extraction/conversion/import of the archive is necessary. The other supported tar layout is `<camera-serial>/cal_file_manifest.json`; both layouts have offline regression coverage.

The program computes its own lenslet centers from the selected RAW rather than importing Lytro's geometric tables as its calibration result. It writes computed `B5151215780/mod_0023.json` next to the *working archive copy*. Therefore the integration runner copies both original files into the output directory first. Image metadata/TIFF, calibration JSON, aligned pickle and reconstructed outputs are all written under `/private/tmp`; no original is altered.

SHA-256 comparison verified originals equal working copies:

- Raw: `ca21c00354bad5538f28148eace7cfbb1c46e391d439a521ece204a38de718bf` (55,171,616 bytes).
- Archive: `d8038f2bedeac25205935edc8dcea9557f7795a764a4d6e60effe5fd046c8afe`.

## Tests and limitations

Passed **28 test cases**: six existing synthetic calibration tests, two existing error tests, three existing CLI tests, one existing point-cloud test, eight existing GUI widget tests, six new offline compatibility/archive/depth tests and two new viewer tests. Some legacy `test_all` cases duplicate their individual methods; counts are unittest executions, not independent algorithms. `pip check` passed. Wheel contents include configuration/icons; sdist independently rebuilds a wheel with isolated setuptools.

The full historical dataset-dependent suite is **not claimed to pass**. `wp12283669.server-he.de` no longer resolves, with both HTTP and HTTPS checked outside the network sandbox. The synthetic pitch-estimator and real-data plotting fixtures are absent. Setuptools emits package-data namespace warnings for legacy data/script directories; required configuration and GUI icons were checked in the wheel. Executable/frozen bundle tests and whole-GUI processing-thread orchestration were not exercised. Core processing and real-result viewer interaction were tested separately.

A `ComplexWarning` occurs during photo color equalization when color-matcher returns complex numerical intermediates that the existing viewpoint array casts to real. Outputs are finite and visibly reconstructed; the underlying numerical behavior was not changed without evidence of an algorithmic defect. Input sensor orientation is preserved.

The immutable Depthy fork reports distribution metadata version 0.1.0 while its Python module retains the upstream version. This is recorded rather than concealed; the exact commit is what identifies the tested dependency. It requires Python >=3.12. Python 3.11 is not supported by this dependency; local macOS acceptance used 3.14.7, and Ubuntu CI covered 3.12–3.14. A direct Git dependency also requires Git/network access and would need a published maintained release before a future PyPI publication of this fork.

Recommended next work: publish a properly versioned maintained Depthy release (or contribute those fixes upstream), replace the dead historical fixture host with reproducible local/synthetic fixtures, investigate color-matcher's complex intermediates, and separately modernize frozen-app bundling/CI and test the GUI processing worker end to end. A separate CPython compatibility workflow runs the offline tests, imports and isolated builds on Ubuntu with Python 3.12, 3.13 and 3.14, using current official checkout/setup-python v7 actions. macOS GUI and real private camera data remain local acceptance tests. The historical bundling/publishing workflow is unchanged.
